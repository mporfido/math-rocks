# Sketch p5.js — `:::p5`

Simulazioni, mini-app e figure interattive scritte in [p5.js](https://p5js.org/).
Le opzioni stanno sulla riga di apertura, il codice JavaScript nel corpo.

```markdown
Posizione: ${a}{a|0|0,10,1}

:::p5 goal height=240 bind=a
const target = 7;
p.setup = () => { p.createCanvas(ctx.width, ctx.height); };
p.draw = () => {
  const a = ctx.model.a ?? 0;       // legge slider e campi numerici della pagina
  // …disegno con p5…
  if (Math.abs(a - target) < 0.001) ctx.complete();  // criterio del goal
};
:::
```

p5.js è caricato dal CDN **solo** nelle pagine che contengono almeno uno sketch.

## Opzioni della riga di apertura

| Opzione | Significato |
| --- | --- |
| `goal` | Flag: rende lo sketch un **goal**. Senza, è pura visualizzazione e non blocca lo step |
| `height=400` | Altezza suggerita del canvas (default 400) |
| `width=600` | Larghezza suggerita (opzionale) |
| `bind=a,b` | Variabili da osservare per `ctx.onChange` e per il redraw degli sketch con `noLoop` |
| `sketch=nome` | Usa uno **sketch riusabile** dal registro (vedi sotto): corpo vuoto |

Ogni altra coppia `chiave=valore` è un **parametro** dello sketch (vedi sotto).

## L'oggetto `ctx` — il ponte con la piattaforma

Lo sketch riceve due argomenti: `p` (l'istanza p5, in *instance mode*) e `ctx`.

| `ctx` | Cosa fa |
| --- | --- |
| `ctx.complete()` | Segnala il completamento del goal (idempotente; no-op se lo sketch non è un goal) |
| `ctx.completed` | `true` se il goal è già stato completato, anche ripristinato da storage |
| `ctx.model` | Valori **live** di slider e campi numerici della pagina (`ctx.model.a`, …) |
| `ctx.set(nome, valore)` | **Scrive** una variabile nel modello dello step: la figura diventa la sorgente dei numeri del testo (vedi sotto) |
| `ctx.onChange(cb)` | Registra `cb(nome, valore)`, chiamata a ogni cambio di variabile |
| `ctx.width` / `ctx.height` | Dimensioni suggerite, da passare a `p.createCanvas(…)` |
| `ctx.setHeight(h)` | Cambia l'altezza del canvas a runtime (es. layout *portrait* su schermi stretti) |
| `ctx.params` | Parametri passati dal markdown (solo sketch riusabili) |
| `ctx.evidenzia(id)` / `ctx.evidenziato(id)` / `ctx.onHighlight(cb)` | Ponte con i passi di un `:::theorem` (vedi [DIMOSTRAZIONI.md](../DIMOSTRAZIONI.md) §5) |

In *instance mode* tutte le funzioni p5 si chiamano sull'oggetto `p`
(`p.createCanvas`, `p.background`, `p.circle`, `p.mouseX`, …), non come globali.

> Il criterio di completamento lo decidi tu: chiama `ctx.complete()` quando la
> condizione che vuoi (una distanza, un punteggio, un click, una sequenza di
> azioni) è soddisfatta.

### `ctx.set(nome, valore)` — la figura che riempie il testo

`ctx.model` legge; `ctx.set(…)` scrive. Serve quando è lo **sketch** a produrre
i numeri: trascini due punti sul piano e accanto alla figura la formula si
compila da sola, in MathJax vero, con i valori di quel momento.

```markdown
> use-mathjs: true

:::p5 sketch=piano-distanza height=360
:::

$$\Delta x = ${dx} \qquad \overline{AB} = ${= sqrt(dx^2 + dy^2)}$$

[Verifica]{check: sqrt(dx^2 + dy^2) == 13}
```

Nello sketch:

```javascript
ctx.set('dx', Math.abs(B.x - A.x));
ctx.set('dy', Math.abs(B.y - A.y));
```

La variabile si comporta in tutto come se venisse da uno slider: aggiorna i
riferimenti `${…}`, i calcoli live `${= …}` e le condizioni `{check: …}`, e
viene salvata nei progressi.

> ⚠️ **Non chiamarlo dentro `draw()`.** `draw()` gira a 60 fotogrammi al
> secondo: scrivere lì significa 60 salvataggi su `localStorage` ogni secondo.
> Chiamalo quando il valore *cambia davvero* — a fine trascinamento, dopo un
> click — e in `setup()` per pubblicare i valori iniziali. (Una scrittura che
> non cambia nulla viene comunque ignorata, ma non è una scusa per il loop.)

## Sketch riusabili (`sketch=nome`)

Uno sketch usato in più punti non va ricopiato nel markdown: il codice vive una
volta sola in `static/sketches/<nome>.js` e lo si richiama **per nome**,
passando i parametri sulla riga di apertura. Il corpo del blocco resta vuoto:

```markdown
:::p5 sketch=rettangoli-divisori n=6 height=360
:::
```

Con un goal e più parametri (procedura guidata per MCD e mcm a partire dalle
scomposizioni: colonne = primi comuni, celle da riempire con gli esponenti):

```markdown
:::p5 goal sketch=mcd-mcm-tabella a=84 b=90 modo=entrambi
:::
```

- `sketch=nome` sceglie la factory `window.P5Sketches['nome']`.
- Ogni coppia `chiave=valore` **non riservata** (diversa da
  `goal`/`height`/`width`/`bind`/`sketch`) arriva allo sketch in `ctx.params`; i
  valori numerici come `n=6` sono convertiti in numeri. Così lo stesso sketch si
  riusa con comportamento diverso.
- Il flag `goal` funziona anche qui.
- Il file è **caricato al volo** solo nelle pagine che lo usano, quindi
  aggiungerne di nuovi non appesantisce le altre lezioni.

### Registrare un nuovo sketch

Crea `static/sketches/<nome>.js` — il nome del file deve combaciare con la
chiave usata in `sketch=<nome>`:

```javascript
(function () {
  window.P5Sketches = window.P5Sketches || {};
  window.P5Sketches['nome'] = function (p, ctx) {
    const n = Number(ctx.params.n) || 6;      // legge i parametri del markdown
    p.setup = () => { p.createCanvas(ctx.width, ctx.height); };
    p.draw = () => { /* …disegno… */ };
  };
})();
```

Gli sketch **inline** restano supportati per i casi usa-e-getta; per riusare o
alleggerire il markdown, preferisci un file.

## Errori tipici

| Sintomo | Causa |
| --- | --- |
| `createCanvas is not defined` | Instance mode: va scritto `p.createCanvas` |
| Lo sketch non si aggiorna muovendo lo slider | Manca `bind=` sulla riga di apertura |
| Lo step non si completa mai | Manca il flag `goal`, oppure `ctx.complete()` non viene mai raggiunto |
| `ctx.params` è vuoto | I parametri funzionano solo con `sketch=`, non negli sketch inline |
